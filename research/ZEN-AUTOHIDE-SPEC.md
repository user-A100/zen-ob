# Zen window-control auto-hide reference

Research date: 2026-10-24. Reference commit: `f2b18c4f6179a3918c0d92f2a7406322cda4ad12` from [zen-browser/desktop](https://github.com/zen-browser/desktop/tree/f2b18c4f6179a3918c0d92f2a7406322cda4ad12). This describes the default Windows-style controls, expanded left sidebar, single-toolbar layout. It is distinct from hiding the sidebar in Compact Mode.

## Search and scope

The existing Zen source checkout, current Obsidian plugin, package manifests, and available tools were inspected before recommending changes. The sparse checkout lacked relevant Git objects; they were fetched from the official public repository and the checkout extended to include `src/zen/compact-mode`, tabs, browser styles/preferences, and `prefs/zen`. The first web/raw and default-proxy reads failed; direct public Git access succeeded. No npm registry search or new dependency was needed: this is a small host-specific layout/event adaptation, and the authoritative implementation is present in the product source. Existing Playwright can validate it.

## Events, focus, menus, and exit

The shared `ZenCompactMode` manager initializes these mouse actions even outside Compact Mode ([init, lines 93–130](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/compact-mode/ZenCompactMode.mjs#L93-L130)).

- Hover targets are sidebar, content navbar wrapper, and actual window controls, in that order ([lines 615–631](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/compact-mode/ZenCompactMode.mjs#L615-L631)). `mouseover`/`dragover` adds `zen-has-hover`; `mouseleave`/`dragleave` schedules its removal after rechecking hover/drag/suppression conditions. `HOVER_HACK_DELAY` defaults to 0ms; requestAnimationFrame applies the removal. The normal toolbar has no sidebar keep-open duration ([lines 737–860](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/compact-mode/ZenCompactMode.mjs#L737-L860)). Therefore ordinary within-window collapse uses the CSS 200ms delay plus 150ms transition, **not** the 1000ms outside-window fallback.
- `zen-compact-mode-active` means an observed toolbar descendant matches `[panelopen]`, `[open]`, `#urlbar:focus-within`, or `[breakout-extend]` (except `.zen-compact-mode-ignore`). It does not mean “Compact Mode is enabled.” The toolbar observer always stays connected ([lines 206–238](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/compact-mode/ZenCompactMode.mjs#L206-L238)).
- `has-popup-menu` tracks a popup owned by that toolbar. A menu stays visible while its popup is open. On popup close, if the mouse is inside the main window the state is released; if outside, it remains until the first returning mousemove ([ZenUIManager.mjs, lines 271–323](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/common/modules/ZenUIManager.mjs#L271-L323)). Removing one reason does not collapse content while another verified reason remains ([CompactMode, lines 662–727](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/compact-mode/ZenCompactMode.mjs#L662-L727)).
- A true exit across the toolbar's top window edge has its own path. Zen tracks the pointer beyond the window with platform support. Current defaults permit 100 CSS px vertically (200 horizontally for sidebars); fallback when tracking is unavailable keeps it open for 1000ms. Returning to content clears it on the first mousemove. This is **not** a generic normal-hover delay ([CompactMode, lines 862–916, 953–1013](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/compact-mode/ZenCompactMode.mjs#L862-L916), [prefs/compact-mode.yaml, lines 17–29](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/prefs/zen/compact-mode.yaml#L17-L29)). Windows uses a native `WH_MOUSE_LL` hook ([ZenMouseTrackerWin.cpp](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/compact-mode/ZenMouseTrackerWin.cpp)).
- Window size mode changes clear stale hover states. Deactivation immediately releases an element held by outside-window tracking ([CompactMode, lines 132–139](https://github.com/zen-browser/desktop/blob/f2b18c4f6179a3918c0d92f2a7406322cda4ad12/src/zen/compact-mode/ZenCompactMode.mjs#L132-L139)).

## Existing implementation gap and adaptation decision

At v0.2.1, `plugin/main.ts` uses `mousemove` against a fixed 100×48 top-right region; it intentionally ignores mouseleave and has no menu/focus/resize/deactivate state model. `plugin/mint-chrome.css` only fades the existing caption container over 120ms and changes its background. It does not reproduce Zen's full-width top reveal strip, 8→34px geometry, 200ms wait, or content compensation.

Recommended minimal solution: **extend existing host controls, without a package or replacement buttons**. Use an independent content-top overlay/reveal surface anchored to the real content bounds. Preserve an 8px entry strip, reveal the full 34px bar using the original 200ms delay and 150ms height/opacity transition, and keep underlying pane geometry unchanged. Retain Obsidian's own window buttons as children/overlaid controls with `no-drag`, while the rest of the bar is draggable. Model hover, keyboard focus, and owned popup hold reasons separately; cancel stale hides on reentry. On hiding completion, disable hit testing of hidden controls. Clear stale state on resize and blur; restore original host DOM/styles on unload. Avoid fixed viewport dimensions and custom native window chrome.

Obsidian does not provide Zen's native global mouse tracker or XUL popup attributes. Do not introduce a global mouse hook just for this behavior. A bounded leave grace period, explicit blur cleanup, native-control hover/focus, and owned DOM menu lifetime tracking are host adaptations; they should be documented as such. Match only popups belonging to this control surface; an unrelated editor menu should not hold the toolbar open. Reduced-motion mode can disable the animation while preserving interaction.

Validation should cover the normal/middle/right parts of the 8px top strip, sustained hover, cancelled quick crossings, entering the native buttons, moving back into content, focus hold/release, owned popup hold/release, window exit and blur, maximize/restore/resize, no content displacement, no fixed viewport after capture, no residual white gutters, and cleanup on disable.
